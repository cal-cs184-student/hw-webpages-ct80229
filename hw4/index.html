Overview

In this assignment I built a real-time cloth simulator using a mass-spring system. I started by constructing a grid of point masses connected by structural, shearing, and bending springs. Then I added simulation through Verlet integration combined with Hooke's law forces and a Provot deformation constraint. I implemented collisions with spheres and planes, then extended the simulator to handle self-collisions using a spatial hash map. Finally, I wrote a set of GLSL shaders for diffuse, Blinn-Phong, texture, bump, displacement, and mirror shading. The most interesting thing I observed was the difference between bump mapping and displacement mapping: even though they share the same height map and lighting math, only displacement actually deforms the geometry, which becomes obvious at silhouettes and at low mesh resolutions.

Part 3: Handling Collisions with Other Objects

Describe your implementation of handling collisions with spheres and planes.

Sphere Collisions

The tangent point is the sphere surface point closest to the mass along the ray from the origin. I started by computing the vector from the origin to the mass' current position. Then, I checked whether its magnitude was less than or equal to the radius of the sphere. If it was, then I calculated the tangent point. Then, I calculated the correction vector from the last position to the tangent point, and set the mass' new position to last_position + correction * (1 - friction). This pulls the mass back to the surface while applying friction.

Plane Collisions

For each point mass, I calculated two distances: the distance from the plane to position, and the distance from the plane to last_position. If the signs of the two distances differ, then we know that, in the last timestep, the mass crossed the plane. Then, I calculated the intersection point and offset it by 0.0001 so that the mass rests above the surface slightly. I scaled the correction vector by 1-friction and applied it.

Part 4: Handling Self-Collisions

Describe your implementation of handling self-collisions.

hash_position was implemented by partitioning space into boxes, each with a dimension of w x h x t. w is set to 3 * width / num_width_points, h is set to 3 * height / num_height_points, and t is set to the larger of w and h. For each position, the coordinate is snapped down the lower corner of its box. Each of the thre box coordinates is combined into a single float using the multipliers 3271, 7919, 104729 (large primes). This minimizes hash collisions.

build_spatial_map was implemented by clearing the hash map and reinserting each point into its bucket by calling hash_position. This occurs at the start of each simulation step.

self_collide was implemented by first looking up its hash bucket to get nearby candidates. A loop is run over each candidate: for each one, we check if the distance between them is less than 2 * thickness. If so, then we need to create a correction vector that will push the mass away from the candidate along the vector between them until it reaches minimum separation. All correction vectors are calculated then averaged and scaled by 1/simulation-steps to keep corrections smooth across substeps. the result is applied to the mass' position. self_collide is called on every single point mass on every single simulation step.

Part 5: Shaders

Explain in your own words what is a shader program and how vertex and fragment shaders work together to create lighting and material effects.

A shader program is a program that runs on the GPU. It consists of a vertex shader and a fragment shader that run in parallel to process all vertices and pixels. The vertex shader runs once for each vertex. Its primary job is to calculate the final clip-space coordinate the rasterizer uses to place the triangle on screen. It also passes forward world space values to the fragment shader. The main job of the fragment shader is to use those values to write a final color using lighting equations. It runs once per pixel. The fragment shader primarily impacts how a surface looks, and the vertex shader primarily impacts the geometry of the surface.

Explain the Blinn-Phong shading model in your own words.

Blinn-Phong categorizes the light that hits a surface into three groups. The first group is ambient: it is a flat, constant color that is added to everything. This ensures no surface goes uncolored (black). The next is diffuse. It models a matte surface. Light hits and scatters equally in all angles. Brightness is only dependent on the surface normal and light direction. Specular is the last— it models shininess. The three groups are weighted via ka, kd, and ks, then summed. A high kd, low ks surface looks like cloth. A low kd, high ks surface looks like metal.
