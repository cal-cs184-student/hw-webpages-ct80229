Part 1: Ray Generation and Scene Intersection

Walk through the ray generation and primitive intersection parts of the rendering pipeline.

For each pixel, I need to take the average of multiple rays firing. To do this, I began with pixel position. At each (x,y) coordinate, I added a random jitter to avoid harsh aliasing, normalized both coordinates to [0,1] by dividing by image width and height, then mapped it onto the virtual sensor at z = -1. The sensor spans from -tan(hFov/2) to tan(hFov/2) horizontally and -tan(vFov/2) to tan(vFov/2) vertically, so the normalized x and y coordinates map to (2x - 1) * tan(hFov/2). Then, the ray is built by creating a vector from the camera origin to the sensor point. The vector is normalized, then rotated at the camera position with that world-space direction, with min_t and max_t set to near and far clip distances.

After the ray is created, we check what it hits. For triangles, I used the Möller–Trumbore algorithm to find if and where the ray crosses the triangle. For spheres, I plug the ray into the sphere equation and solve the quadratic. The normal is the unit vector from the sphere center to the hit point. In both cases, if a hit is valid, we update the ray's max_t and then record the following into the Intersection struct:

  1. The hit time t
  2. The interpolated normal
  3. The primitive pointer (what object was hit)
  4. The surface BSDF

Explain the triangle intersection algorithm you implemented in your own words.

I used the Möller–Trumbore algorithm, which finds two things: where along the ray a hit occurs (t), and where inside the triangle it lands (u,v). This can be broken down into four major steps.

  1. Check if the ray is parallel. I compute two edge vectors, then compute the determinant. If the determinant is near 0, then the ray misses since it's parallel to the triangle.
  2. Finding the barycentric coordinates. The first coordinate is u = dot(tvec, pvec) / determinant. If u is outside [0, 1], the intersection point is outside the triangle. The second coordinate is v = dot(ray.d, qvec) / determinant. If v < 0 or u + v > 1, then the point is outside the triangle.
  3. Find the hit distance t = dot(edge2, qvec) / determinant. If t isn't within the ray's valid range [min_t, max_t], reject the hit.
  4. Finally, interpolate the normal. The third barycentric weight is computed as w = 1 - u - v, and we interpolate the surface normal as w * n1 + u * n2 + v * n3, then normalize it.

Part 2: Bounding Volume Hierarchy

Walk through your BVH construction algorithm. Explain the heuristic you chose for picking the splitting point.

This is a recursive algorithm. We start each step by creating a bounding box over all the primitives in the current range. The recursive check: If the number of primitives we have is less than or equal to max_leaf_size, then we make a leaf node that stores the range and return. If we don't return, then we're still above max_leaf_size. In this case, we choose a split axis based on whichever dimension spans the largest range. The split point is computed as the average centroid position. Then, classify each primitive: if its centroid is below the split point, it goes left. Otherwise, it goes right. In the case that all the primitives are placed on one side, they are split evenly by index. After writing the order back, we recursively construct left and right child nodes and attach them to the current node.

Part 3: Direct Illumination

Walk through both implementations of the direct lighting function.

Uniform Hemisphere Sampling: In this method, we shoot rays in random directions across the hemisphere above the point. This is how we'll estimate the amount of light hitting the point. For each of num_samples iterations, we calculate how much a ray contributes to the surface's reflectance, the light's brightness, and the angle of the incoming light. To do so, we draw a random direction in the hemisphere using hemisphereSampler->get_sample(). Then, that direction is rotated into world space and casts a shadow ray. If the shadow ray hits a surface, we check whether that surface emits light. If so, we can use the reflection equation. Each sample contributes to an accumulator, which is divided by num_samples to get our estimate.

Importance Sampling Lights: In this method, we don't rely on sampling random directions. In uniform hemisphere sampling we were unsure whether each direction would point toward a light source; in importance sampling, we select directions that we know will point to a light source. We loop over each light and call sample_L. For point lights, we only take one sample (since all would be the same). For area lights, we take the average of ns_area_light samples. Once we get the emitted radiance, direction toward the light, distance to the light, and the pdf of the sample from sample_L, we then find the BSDF and get the cosine term. Afterward, we check the cosine: if it's negative, the light is behind the surface and is skipped. If positive, we cast a shadow ray from the hit point to the light. If this ray hits nothing, then the light is visible. In this case, bsdf * emittedRadiance * cosine / pdf is added to the accumulator.

The first image (importance sampling) and second image (uniform hemisphere sampling) were rendered with the same settings, making the difference in quality stark. Importance sampling produces a clean, smooth result with well-defined soft shadows and accurate color on the walls, while hemisphere sampling produces a heavily grainy image where the entire scene is covered in noise and the bunny is difficult to distinguish from the background. The core reason is where each method concentrates its samples. Hemisphere sampling fires rays in random directions across the entire upper hemisphere — the vast majority of those rays miss all light sources entirely and contribute nothing, so most samples are wasted. Importance sampling fires rays directly toward each light source, meaning nearly every sample carries useful information. With the same sample count, importance sampling has far lower variance because it is unlikely to miss the light, while hemisphere sampling must get lucky to hit it. This difference is especially visible in the soft shadow region under the bunny, which is smooth and gradual under importance sampling but nearly invisible under the noise of hemisphere sampling.

Part 4: Global Illumination

Walk through your implementation of the indirect lighting function.

My indirect lighting function provides us with an estimate of how much light hits a surface point after at least one bounce. It is recursive, called once for each additional bounce of light. First, the function adds direct lighting to the accumulator. If the flag is false, we only return light from deeper bounces. Then, we have the recursive check: if the depth is 1 (it decrements each call), then we return L_out. If the function continues, we randomly sample an incoming direction. We save the sampled direction, and write the probability density into pdf. Then, to avoid tracing paths infinitely, we use Russian Roulette termination. Paths are ended with a 0.3 probability, and continue with a 0.7 probability. Paths that survive have their contribution divided by continuationProbability to keep the estimator unbiased. In paths that survive Russian Roulette, we rotate sampledDirectionObject to world space. Then, the next ray is constructed and tested against the BVH. If it hits something, then we call the function recursively on the new hit to get the radiance from that direction. Its contribution is added to L_out as bsdfValue * indirectRadiance * cosineTheta / pdf / continuationProbability.

Part 5: Adaptive Sampling

Explain adaptive sampling. Walk through your implementation of the adaptive sampling.

Adaptive sampling aims to reduce render times by focusing on pixels that are difficult to estimate (typically pixels in noisy or complex areas), and placing less emphasis on pixels in easy-to-estimate areas. Sampling ends early when a pixel converges to a stable value. In practice, this means that simple regions in a scene, like plain walls, will converge quickly and only require a few samples. Complex regions, like areas with a lot of indirect light, will require a lot more samples.

My implementation modifies the sampling loop from Part 1 in three main ways. First, we need to track running statistics. I created two variables runningS1 and runningS2, which represent running sums (for per-sample illuminance values and squared illuminance values). After each sample, illuminance is computed and added to both accumulators. Second, convergence is checked periodically. After every samplesPerBatch samples, which defaults to 32, I computed the mean and variance. These two values are used to create a 95% confidence interval, which tells us how uncertain we are about the true mean. If we are 95% confident that the true mean is within 5% of the estimate we have, then we can break the loop since the pixel has converged. Third, I output the actual sample count. After the loop, totalRadiance is divided by samplesCompleted (as opposed to maxSamples) to get the correct average when exiting early. samplesCompleted is also written into sampleCountBuffer to generate the sampling rate visualization.
